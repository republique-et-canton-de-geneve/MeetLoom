# Rich text and preparation

The editor uses the free [Tiptap / ProseMirror](https://tiptap.dev/docs/editor/getting-started/overview) extensions: bold, italic, underline, bulleted and numbered lists, nested tasks, links, color, and highlighting. No Tiptap subscription or remote service is used. Only one active cell mounts the editor, keeping large agendas manageable.

Legacy text fields remain compatible. A formatted value contains `meetloom:richtext:v1:` followed by the JSON document. `shared/richtext.ts` limits its size to 30,000 characters, depth to 24, and node count to 2,000. Validation accepts only known structure and attributes. Links allow http, https, and mailto without credentials; colors use simple HEX values. The [Tiptap static renderer](https://tiptap.dev/docs/editor/api/utilities/static-renderer) receives explicit React components: user-provided HTML is never executed. Legacy text or an invalid document is displayed literally.

`RichTextEditor` accepts `value`, `onChange`, `disabled`, `ariaLabel`, `placeholder`, `compact`, and an optional limit. `RichText` displays a read-only value. PublicAgenda and PrintableAgenda use the same rendering after projection of the allowed columns. Text-only consumers, including CSV, PowerPoint text, and AI context, use `richTextToPlain`; spreadsheet expressions remain neutralized after conversion. Word export also interprets the rich document structure. JSON saves preserve the complete format. See [exports.md](exports.md) for format-specific behavior and validation limits.

`Column.kind` distinguishes text, tasks, and materials. The goals, instructions, background, tasks, and materials presets create internal columns hidden from the table by default; their values remain available in the details view. The tasks panel aggregates checklists from the day's fields, including groups and rooms, and offers all/to-do/completed filters. A checkbox uses its document path and exact source value: a concurrent text change rejects a stale check. The materials panel aggregates lines from `materials` columns, sorted by agenda order or alphabetically.

Adding from the panel atomically creates or reuses an internal column of the same type; an existing public column is never implicitly reused. Imports preserve the type but force imported columns to an internal audience. A checklist does not grant any additional read permission. Implemented mentions and notifications are documented in [team-comments.md](team-comments.md); remaining comparative checks and reporting coverage are tracked in [product-parity.md](product-parity.md).

Targeted tests cover HTML escaping, malicious URLs, JSON structure and limits, nested lists, stale checkbox changes, atomic private-column creation, recursive imports, and CSV exports. Browser QA separately checks selection and keyboard interactions.

PPTX: `pptxgenjs` declares an old `image-size` dependency. The override to `^2.0.4` avoids vulnerabilities in the transitive version; text export was checked with this override, and npm audit reported no vulnerabilities on September 23, 2026. PPTX can include locally generated form QR codes. Block attachments remain excluded, and form-response images are not embedded in these exports.
